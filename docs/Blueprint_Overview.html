FileForge Blueprint

Comprehensive technical reference — v0.1.7 — 2026-05-19

Overview

FileForge is an AI-powered file organizer that runs entirely on your local machine. It scans directories, reads file contents, and uses a locally hosted LLM to classify files into meaningful folder taxonomies — no cloud services, no data leaving your system.

The core problem it solves: file systems accumulate noise over time. Duplicate downloads, stale drafts, misnamed exports, and forgotten temp files pile up in ways that are expensive to clean manually but too risky to automate blindly. FileForge provides an intelligent, auditable, and reversible process for reclaiming that space and restoring order.

Design Principles

Offline-First

Classification via Ollama on your local machine. No cloud APIs. No data leaves your system.

Safe by Default

Phase 1 reads and reports only. All destructive operations require explicit commands + dry-run preview.

Transparent

Every scan, classification, and file action is recorded to SQLite with full metadata. Nothing happens silently.

Graceful Degradation

If Ollama is unavailable, scans continue with rule-based fallback. If a file can't be read, it's recorded and skipped.

Quick Start

# Install from source
git clone https://github.com/coreconduit/fileforge.git
cd fileforge
bash scripts/install.sh

# Pull Ollama models (optional — skip with --no-classify)
ollama pull qwen3:4b
ollama pull nomic-embed-text

# Read-only scan (no files changed)
fileforge scan ~/Documents

# Fast scan without AI
fileforge scan ~/Documents --no-classify

# Open the web UI
fileforge server
# → http://localhost:8082

# Preview organization plan
fileforge organize ~/Downloads --dry-run

# Find and review duplicates
fileforge dupes ~/Documents
💡
FileForge makes no changes during scan. Files are only moved or deleted when you run organize or dupes — and only after confirming or removing --dry-run.

Data Flow

CLI Scan Pipeline

  1. Scanner.scan() — recursive walk, creates FileRecord per file
  2. hash_file() — SHA-256 in 64KB chunks → FileRecord.sha256
  3. find_exact_duplicates() — group by hash, flag is_duplicate
  4. extract_snippet() — dispatch to extractor; return None on error
  5. classify_file() — Ollama REST call → category string (skipped with --no-classify)
  6. SessionDB.save_records() — bulk insert; complete_session() stamps completed_at
  7. Phase 2 analysis — embeddings / staleness / versions (only with --phase-2)
  8. print_scan_summary() — Rich table to stdout

Web UI Async Scan

  1. Browser: POST /api/scan with directories + options
  2. Server: validates dirs, builds subprocess cmd, runs in thread pool, returns job_id
  3. Browser polls: GET /api/job/{job_id} until status is complete or error
  4. Browser: GET /api/session/{session_id} → full FileRecord list for rendering

Database Schema

Location: ~/.fileforge/sessions.db (configurable via output_dir).

REST API

Served by api/server.py (FastAPI). Start with fileforge server.

GET /api/health
Health check. Returns {"status":"ok","version":"0.1.7"}
POST /api/scan
Start async scan. Body: {"directories":["~/Docs"],"no_classify":false,"phase_2":false}. Returns job_id. HTTP 409 if a scan is already running.
GET /api/job/{job_id}
Poll scan status. Returns {"status":"running|complete|error","session_id":42}
GET /api/stats
Aggregate stats from latest scan + up to 100 file records.
GET /api/sessions
List all scan sessions, newest first.
GET /api/session/{session_id}
All FileRecord objects for a session.
GET /api/config
Current FileForgeConfig as JSON.
POST /api/config
Validate and persist a new configuration to fileforge.toml.
GET /api/browse?path=
List non-hidden subdirectories at path for the directory picker widget.

Configuration

Config is searched in order: --config CLI flag → ~/.config/fileforge/fileforge.toml (XDG) → ~/.fileforge/fileforge.toml (legacy) → built-in defaults.

[general]
scan_dirs = ["~/Documents", "~/Downloads"]
output_dir = "~/.fileforge"
max_depth = -1            # -1 = unlimited
max_extract_size = 52428800

[ai]
classification_model = "qwen3:4b"
embedding_model = "nomic-embed-text"
ollama_url = "http://localhost:11434"
snippet_length = 2000
category_hints = """
I work with nonprofits and embedded systems.
Priority categories: contracts, source-code, documentation.
"""

[duplicates]
similarity_threshold = 0.92
semantic_dedup = true

[staleness]
stale_days = 365
junk_patterns = ["Thumbs.db", ".DS_Store", "~$*", "*.tmp"]
temp_patterns = ["*.bak", "*.swp", "*.orig"]
detect_versions = true

[ignore]
patterns = [".git", "node_modules", "__pycache__", ".venv"]

Per-directory overrides: create a .forgeignore file using gitignore glob syntax. Patterns are merged with [ignore] from the TOML config.

Installation

# Development install (recommended)
git clone https://github.com/coreconduit/fileforge.git
cd fileforge
bash scripts/install.sh        # interactive: venv, models, optional extras, systemd

# Manual install
pip install -e ".[dev]"        # core + dev deps
pip install -e ".[ann]"        # add near-dup ANN support
pip install -e ".[ocr]"        # add OCR support (+ Tesseract binary)

Systemd Services (Linux)

# Install both scan timer and web server
bash src/fileforge/systemd/install.sh

# Or selectively
bash src/fileforge/systemd/install.sh --scan    # scan timer only
bash src/fileforge/systemd/install.sh --server  # web UI only

# Manage
systemctl --user status fileforge-scan.timer
systemctl --user status fileforge-server.service
journalctl --user -u fileforge-scan.service

Ollama Setup

ollama pull qwen3:4b          # ~2.5 GB classification model
ollama pull nomic-embed-text  # ~270 MB embedding model (Phase 2)
ollama list

Pre-release Check

bash scripts/check.sh         # pytest + black + ruff — must pass clean

Gap Analysis

Discrepancies between documented design and current codebase, as of v0.1.7.

Code Gaps

extractor/xlsx.py — Not implemented Medium
openpyxl is installed but no XLSX extractor module exists. Spreadsheet files produce no text snippet; classification falls back to filename only.
extractor/image.py — Not implemented (OCR) Medium
pytesseract and Pillow are installed but no OCR extractor exists. Image files are scanned and hashed but produce no text snippet.
actions/logger.py — Does not exist Low
Previously documented as a standalone module. Action logging is implemented through SessionDB.log_action() in db.py. Functional workaround in place. Documentation corrected.
actions/prune.py — Not exposed in CLI Low
Empty-directory removal runs automatically after organize but there is no standalone fileforge prune command.
RTF / EPUB extractors — Planned Low
Mentioned in CHANGELOG as upcoming. No dependency installed yet. Use striprtf for RTF, ebooklib for EPUB.
